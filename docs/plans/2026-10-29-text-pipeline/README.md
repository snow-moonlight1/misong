## 产品决策

1. 第四步从并列编码选项升级为多个交付方案；每个方案内部按顺序处理文字，最后输出纯文本或视频。沿用第二步添加、删除、排序、预览的交互，文件打包层和文字处理层使用各自的模型。
2. 支持裸链接→视频、魔曰→视频、兽曰→视频、魔曰→Base64→视频，以及现有纯文本文案。复用现有 encoders，不改第三方 vendor。
3. 采用 `.tkey` 作为文案还原钥匙的扩展名，界面名称为“文案还原钥匙”。它保存处理配方、必要的层密钥和校验信息。与 `.mskey` 一样，明确选择导出才写入；持有钥匙即获得相应还原能力。
4. 文案钥匙首版只提供显式本地导出和用户自行交付，不因导出而自动上传。`.tkey` 不嵌入它自身解锁的视频，以免循环依赖，也不存入普通任务、日志或诊断。
5. 当前主线通过官网 RPA 自动写入、读取及解锁视频。密送负责文字链、钥匙和任务编排，可在一个入口完成视频＋`.tkey` 的还原，但视频步骤依赖官网与网络。不要把网页在设备内计算等同于应用离线可用，也不声称是自主编解码。
6. 载体接口区分逻辑格式与具体实现，集中管理选择器、超时与错误。将来取得授权或完成独立兼容时可以替换实现，复用文字链与 `.tkey`。两份净室提示词及隔离约定保持备用，不要求当前执行者做协议研究。
7. 首版聚焦本地视频画面载体的写入、读取及密码解锁。B 站链接取流另行规划，当前只有用户主动打开官网和手动交接文字的路径；音轨、混合模式、自定义区域未实测前不开放，首版不做视频投稿。

## 钥匙与还原约定

- 每个交付方案生成独立钥匙，包含格式版本、方案标识、由内到外的层序、各层编解码参数/兼容版本、密钥槽及文案摘要。还原时逆序处理。
- 钥匙不保存原文或完整中间文案，避免它变成第二份直接交付的资源；校验所需摘要与算法参数可以保存于封装载荷。
- `.tkey` 与 `.mskey` 使用独立 magic/type/version，不能只凭扩展名分流。首版不改变现有 `.mskey` 文件格式与还原语义。
- 复用已审查的封装思路及 cryptography AESGCM；如抽公共底层，必须保留 `.mskey` 旧样本兼容。随机封装钥匙与密文同行，只用于避免可读密码清单及检测意外损坏，不提供持有者隔离或来源认证。
- 视频转码会改变 MP4 字节。原始导出文件的 SHA-256 可用于本地产物识别，但不作为转码视频唯一的准入条件；提取并解锁后的 UTF-8 载荷及各反向步骤应与钥匙摘要一致，最终原文校验通过才交付。文本不做隐式 trim、换行或 Unicode 归一化。
- 密送用 `.tkey` 编排逆序还原：仅把本次外层视频密码交给官网页面，提取文字后本机解内层；不把整个钥匙交给网页。官网不会因此认识 `.tkey`。用户自行操作官网时才需要手动完成这些步骤。
- 无 `.tkey` 仍保留手动指定处理顺序与逐层输入密码的路径；缺钥匙不能让普通无密码视频无法读取。非可逆的 trunc 不允许进入可导出还原钥匙的链。

## 执行顺序

需要多个 agent 协作时使用[并行分包与派发模板](PARALLEL.md)：S 先冻结接口，A/B/C 并行，随后 D/E 并行，S 统一接线验收。下方 01—05 是功能依赖顺序，不应直接作为五个同时修改共享文件的包。

按 01→02→03-RPA→04→05 顺序实施。03 先用合成视频验证少量关键操作，再完善集成；不等待净室行为规范、作者授权或 B 站取流实现。未来独立兼容以用户另行启动为准。

| 计划 | 交付 | 依赖 |
|---|---|---|
| [01 文字处理链](01-text-chain.md) | 类型约束、旧方案迁移、纯文字正逆向 | 无 |
| [02 文案钥匙](02-text-key.md) | `.tkey` 导出读取、CLI 还原、敏感文件规则 | 01 |
| [03 帧语官网 RPA](03-framewords-rpa.md) | 自动写入/读取/解锁、下载与重新读取核对 | 01、02 |
| [04 发布与桌面接线](04-integration.md) | 第四步层编辑、任务续跑、文案还原入口 | 01、02、03 |
| [05 验收与文档](05-verification.md) | 回归、预览、能力边界及用户文档 | 04 |

网站/授权核查保存在 `RESEARCH.md`，不能据此把帧语自有代码复制进发行包。它含原实现检查线索，不在未来净室角色的输入白名单内。工作区既有 v0.2 改动来自此前工作，实施时不得覆盖或清空。

## 完成条件

- 旧 `schemes` 多选仍产生多个独立结果，不误迁移成串行链。
- 纯文本与帧语视频均可以按明确配方还原；原始文本逐字一致，有钥匙时最终摘要通过；失败不会交付部分解码结果。
- 字符膨胀、不可逆算法、输入类型错误、密码缺失、媒体解码失败与取消均有明确处理；不自动截断文案。
- 网盘分享已成功而第四步失败时，显示“分享完成、文案未完成”，只续跑第四步，不再次上传分享。每份方案独立保存成功状态。
- `.tkey` 默认忽略、明确导出、清理保留，密码不进入任务、模板、普通设置、日志、诊断或测试快照。
- 官网生成的视频保存后必须独立重新读取，载荷逐字一致；本地视频＋`.tkey` 由密送自动调用官网提取/解锁并本机完成文字链。断网/官网不可用时明确失败且可重试，已提取的纯文字仍可离线处理。
- 日常 pytest 使用自制模拟页面；真实官网测试单独显式执行，只用合成素材，不访问真实网盘、不发布真实资源，不将第三方脚本或现场文件提交 Git。平台转码另列验证，不由一次本地文件回读推定。
