# 路线图

> 规划文档，不是承诺。顺序会随反馈和网盘页面变化调整。当前版本：0.1.0。

## 排序原则

1. **接收方优先**：接收方人数最多、最不熟悉工具，还原体验决定项目口碑。
2. **先能排障，再扩大使用面**：网盘改版是最大的维护成本；先让问题能被快速定位，再做安装包和批量。
3. **安全默认**：密码默认不落盘；链接、提取码、Cookie 不进日志和报告；任何自动发布或重传都需要用户确认。
4. **可离线测试的先做**：不依赖真实网盘就能验收的功能风险最低。

## 总览

| 版本 | 主题 | 功能 | 规模 |
| --- | --- | --- | --- |
| 0.2 | 好用、好排障 | ① 接收方一键还原 · ⑧ 登录态检查 · ④ 驱动自检 · ⑦ 诊断包导出与模板导入导出 · ⑨a 智能体 Skill 文档 | 中 |
| 0.3 | 好安装 | ③ 打包 exe / 安装器 + 版本检查 · ⑥ 密码生成器与组合导出 | 大 |

编号沿用需求清单：① 一键还原 ② 链接体检 ③ 打包 ④ 驱动自检 ⑤ 批量队列 ⑥ 密码生成 ⑦ 模板与日志导出 ⑧ 登录态检查 ⑨ 智能体发布。

## 前置工作（跨版本）

这些不是用户可见功能，但多个功能依赖它们，应最先完成：

- **数据目录可配置**：`rpa/runtime.py` 用源码位置推算仓库根，`rpa/state`、`runs` 都在仓库内。非可编辑安装或打包后会失效。改为 `MISONG_HOME` 环境变量，默认 `%LOCALAPPDATA%\misong`，源码运行时保留现有位置并提供迁移。③ 必需，⑤⑦ 受益。
- **统一脱敏模块 `misong.redact`**：分享链接 ID、提取码、解压密码、Cookie、用户目录路径替换为占位符，配单元测试。④⑦②⑨ 共用。
- **驱动可选接口**：在 `DiskDriver` 上增加 `check_login()`、`selfcheck()`、`check_share(url, code)`，基类默认“不支持”，界面按能力显示。⑧④② 共用。
- **结构化日志**：`logging` + 文件轮转，替代散落的输出，供 ⑦ 收集。

## 0.2 好用、好排障

### ① 接收方一键还原

- **命令**：`misong restore <文件或文件夹> [--text 分享文案] [--out 目录]`。
- **自动识别**：`.001`、`.partN.rar`、`.z01` 等分卷，`.misongsplit.json` / `.sha256` 清单，MP4 外壳，多层嵌套。
- **流程**：检查分卷齐全 → 合并并校验 → 逐层解包（复用 `unwrap --chain-pwd` 的自动识别）→ 缺密码时逐层询问；若提供分享文案，先解码并自动带入其中的口令。
- **桌面端**：新增“还原”页：拖入下载文件夹、粘贴文案、一键还原；显示每层结果。
- **错误提示**：缺分卷（列出缺哪几卷）、密码错误（第几层）、校验不符（哪个文件）三类必须给出明确中文说明。
- **验收**：现有所有打包预设的产物都能一键还原；三类错误各有离线测试。

### ⑧ 登录态有效性检查

- 现状：账号页已有单盘“检测”（有头浏览器），状态分为未登录 / 已登录 / 已检测 / 已过期 / 网络错误。
- **批量检查**：`misong account check --all [--headless]` 与账号页“全部检查”。只打开文件页判断登录状态，不上传、不改动。
- **发布前预检**：开始任务前只检查本次会用到的网盘；过期则提示先重新登录，避免跑到中途才失败。
- **注意**：部分网盘无头模式会触发风控，失败时回退有头；检查结果不记录 Cookie。
- **验收**：6 个网盘的“已登录 / 已过期”两种状态都能判定正确；预检能拦住过期账号。

### ④ 驱动自检

分三级，默认只做前两级：

1. **环境**：`misong doctor` 检查 Python、依赖、Playwright、浏览器通道、7-Zip、Node。
2. **只读选择器**：`misong selfcheck --disk <盘>`，打开网盘页面，逐个确认上传、新建文件夹、分享入口等关键元素存在。每个驱动声明自己的关键选择器清单，不做任何写操作。
3. **金丝雀（可选）**：上传 1 KB 文件到 `misong-selftest/`，创建分享、读回、删除。

- 失败时保存截图和页面到私密状态目录，并生成脱敏报告（与 ⑦ 共用打包逻辑）。
- Issue 模板要求附自检报告。
- **验收**：人为改坏一个选择器，自检能准确指出是哪一步、哪个元素失败。

### ⑦ 诊断包导出与模板导入导出

- **诊断包**：`misong diag export` 与设置页“导出诊断包”，内容为版本、系统、依赖版本、日志、最近任务的计划文件（已脱敏）、失败快照清单。截图默认不包含，勾选时提示可能含账号信息。
- **模板**：导出为带 `schema_version` 的 JSON，只含选项，不含密码和账号；导入时校验字段，名称冲突时自动重命名。
- **验收**：诊断包中检索不到任何真实链接、提取码、密码和 Cookie（用固定样本做测试）。

### ⑨a 智能体 Skill 文档（提前做，成本低）

- 编写 `skills/misong/SKILL.md`：教智能体用现有 CLI 完成打包、发布、续跑、还原、编解码，并写明安全约束（登录由人完成、发布前确认、不回显密码）。

## 0.3 好安装

### ③ 打包 exe / 安装器 + 版本检查

- **发布方完整版**：PyInstaller onedir（Nuitka 作备选，权衡体积与误报）。不内置 Chromium，使用系统已装的 Chrome / Edge 通道；7-Zip 已随附。
- **Node 依赖**：乱码编码器需要 Node。方案二选一：随附 `node.exe`，或检测系统 Node，缺失时提示改用在线版。
- **安装器**：Inno Setup，安装到用户目录，无需管理员权限；依赖前置工作“数据目录可配置”。
- **接收方便携版**：只含还原和解码，不含 Playwright，单文件 exe，体积尽量小。
- **版本检查**：启动时查询 GitHub Releases 最新版本，只提示不自动下载；离线或失败时静默；可在设置中关闭。
- **CI**：GitHub Actions（`windows-latest`）跑测试、打包、上传构件；推送标签时自动建 Release 并附 SHA-256。
- **风险**：未签名程序会触发 SmartScreen 警告，PyInstaller 产物易被杀软误报。文档说明原因并提供校验值。

### ⑥ 密码生成器与组合导出

- 用 `secrets` 生成；可选长度、字符集，默认排除易混字符（`0O1lI`）；提供易读的词组模式。可每层独立或统一。
- 发布完成后可**显式**导出“文案 + 密码”组合（文本 / Markdown / 剪贴板），导出前提示明文风险，并建议文案和密码分开发送。
- 默认仍不保存密码。若用户为了补链（②）选择保存，使用 Windows DPAPI 加密并明确告知风险。

## 0.4 规模化

### ⑤ 批量 / 队列发布

- 现状：一次一个任务，按网盘加独占锁。
- **队列**：持久化队列文件；每项 = 源文件 + 模板；默认顺序执行；单项失败不阻塞后续，可重试。
- **任务中心**：排队 / 运行 / 失败 / 完成，支持暂停、取消、调整顺序。CLI：`misong queue add|list|run`。
- **风控**：每项之间随机间隔，可配置每盘每日上限。
- 依赖 ⑧（开跑前统一预检）和 ⑥（批量生成密码）。

### ② 链接体检与一键补链

- **体检**：在不带登录的独立浏览器上下文里打开分享页，判定为正常 / 已失效 / 已取消 / 文件丢失（迅雷曾出现“分享仍在但无文件”）/ 需要验证 / 未知。默认手动触发，可选每天一次（应用内定时或 Windows 任务计划）。结果写回任务记录，失效项在界面标红。
- **补链**（必须用户确认，不自动重传）：
  - 打包产物仍在：复用已保存任务，只重跑失效阶段的上传和分享。
  - 产物已清理：需要原文件和密码重新打包（密码不保存，需用户输入，或使用 ⑥ 的可选加密保存）。
  - 中转链：只重建失效那一跳，并更新最终文案（复用现有回填机制）。
- **范围**：先做百度、夸克，再逐盘扩展。注意匿名访问频率。

## 0.5 智能体

### ⑨b CLI 机器可读输出 + MCP 服务

- **CLI 稳定化**：所有子命令支持 `--json` 输出和规范的退出码；密码只能通过环境变量、标准输入或文件传入，不经命令行参数。
- **MCP 服务**：`misong mcp`（标准输入输出，作为可选依赖）。工具：状态与自检、账号检查、打包、发布、任务列表与续跑、还原、编解码。
- **安全约束**：发布默认先返回计划预览，需带确认参数才执行；不提供登录工具（登录必须由人在浏览器完成）；工具结果不回显密码；可限制允许访问的目录。

## 暂不做

- 自动处理验证码、绕过风控、保存账号密码自动登录。
- 无人确认的自动重传。
- 内置网盘下载器：接收方仍使用网盘官方网页或客户端下载。
