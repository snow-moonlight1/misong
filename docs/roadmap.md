# 路线图

> 当前版本 v0.2.0（2026-10-31），上一发布 v0.1.0。本轮已按用户要求补齐原 v0.2 必需范围，实际验收与限制以[发布记录](releases/0.2.0.md)为准，后续版本顺序仍会随反馈调整。

## 排序原则

1. **接收方优先**：接收方人数最多、最不熟悉工具，还原体验决定项目口碑。
2. **先能排障，再扩大使用面**：网盘改版是最大的维护成本；先让问题能被快速定位，再做安装包和批量。
3. **安全默认**：密码默认不落盘；链接、提取码、Cookie 不进日志和报告；任何自动发布或重传都需要用户确认。
4. **可离线测试的先做**：不依赖真实网盘就能验收的功能风险最低。

## 总览

| 版本 | 主题 | 功能 | 规模 |
| --- | --- | --- | --- |
| 0.2 | 一站式还原与文案交付、好排障 | ① 接收方一键还原 · ⑩ 文案处理链、`.tkey` 与帧语官网 RPA · ⑧ 登录态检查 · ④ 驱动自检 · ⑦ 诊断包与模板 · ⑨a Skill 文档 | 中至大（以网页集成为界） |
| 0.3 | 好安装 | ③ 打包 exe / 安装器 + 版本检查 · ⑥ 密码生成器与组合导出 | 大 |
| 0.4 | 规模化 | ⑤ 批量 / 队列发布 · ② 链接体检与一键补链 | 大 |
| 0.5 | 智能体 | ⑨b CLI 机器可读输出 + MCP 服务 | 中 |

编号沿用需求清单：① 一键还原 ② 链接体检 ③ 打包 ④ 驱动自检 ⑤ 批量队列 ⑥ 密码生成 ⑦ 模板与日志导出 ⑧ 登录态检查 ⑨ 智能体发布。⑩ 为 2026-10-29 新增的文案处理链与帧语网页集成。

## 前置工作（跨版本）

这些不是用户可见功能，但多个功能依赖它们，应最先完成：

- **数据目录可配置**：`rpa/runtime.py` 用源码位置推算仓库根，`rpa/state`、`runs` 都在仓库内。非可编辑安装或打包后会失效。改为 `MISONG_HOME` 环境变量，默认 `%LOCALAPPDATA%\misong`，源码运行时保留现有位置并提供迁移。③ 必需，⑤⑦ 受益。
  0.2 开发版已实现路径解析、桌面/CLI 接入与显式复制迁移，见[数据目录](dev/data-home.md)。
- **统一脱敏模块 `misong.redact`**：分享链接 ID、提取码、解压密码、Cookie、用户目录路径替换为占位符，配单元测试。④⑦②⑨ 共用。
  基础模块及桌面日志/doctor 出口已接入，边界见[脱敏说明](dev/redaction.md)。
- **驱动可选接口**：在 `DiskDriver` 上增加 `check_login()`、`selfcheck()`、`check_share(url, code)`，基类默认“不支持”，界面按能力显示。⑧④② 共用。
- **结构化日志**：`logging` + 文件轮转，替代散落的输出，供 ⑦ 收集。
  0.2 已接入白名单结构化任务事件及轮转，诊断可收集；不持久化任意请求、原文和密码。可选驱动接口已定义，未实现的分享体检默认报告不支持，实际分享体检仍属 0.4。

## 0.2 好用、好排障

### ① 还原钥匙与接收方一键还原（开发版已实现，待随 0.2 发布）

- **发布方**：明确选择导出 `.mskey`，携带完整处理层序、分卷校验和当前各层密码。可仅留本地、随本体分享，或随第一跳指引交付。
- **命令**：`misong nest ... --export-key`；`misong publish ... --restore-key-location local/body/hop`；
  `misong restore <文件或文件夹> [--key-file 资源.mskey] -o <空目录>`。
- **流程**：读取钥匙 → 匹配最终产物及校验所有分卷 → 按清单自动合卷、剥离 MP4、逐层解包 → 成功后交付结果。
  钥匙在同目录且唯一时 CLI 可自动发现；不要求接收方逐层输入密码。
- **桌面端**：“一键还原”页支持一起拖入压缩包/分卷文件夹和钥匙，显示处理层进度及输出目录。
- **边界**：钥匙是可直接解密的凭据，二进制封装避免直出密码 JSON，不承诺阻止持有者解析。
  旧包没有保存的密码仍不能凭空恢复，继续使用原 unest/unwrap 密码链。
- **验收**：真实本地嵌套、门面视频、分卷和重新套层还原；缺卷、校验不符、错密码、恶意文件名及损坏钥匙均有离线测试。
- **后续扩展**：无钥匙交互还原、分享文案带入口令，以及原生 RAR/ZIP 分卷识别另行实现；不将其计作本轮已完成范围。

并行任务与文件所有权见 [v0.2 并行分工](plans/2026-10-26-v0.2-parallel.md)。

### ⑩ 第四步文案处理链、`.tkey` 与帧语官网 RPA（已集成）

- **交付模型**：第四步复用第二步的层编辑体验，每份方案按顺序处理文案，末端输出纯文本或视频；多个方案独立输出。支持裸链接→视频、魔曰/兽曰/Base64→视频及多层组合；现有多选不能被误迁移成串行链。
- **文案还原钥匙**：显式导出 `.tkey`，封装文案层序、必要密钥和摘要。用户在密送内选择本地视频与钥匙，程序经官网 RPA 读取/解锁视频，再在本机逆序解文字层并验证原文。操作可以一站式完成，但视频层依赖官网和网络；纯文字层与原有 `.mskey` 还原仍可离线。
- **技术主线**：先集成官方正常网页写入、读取与解锁，复用现有 Playwright 基础能力；选择器集中管理。以可替换载体接口隔离网页依赖，钥匙不保存页面选择器。当前不研究或移植帧语协议，不复制其自有脚本到发行包。
- **首版范围**：本地视频画面载体的无密码/有密码正逆向。音轨、混合模式、自定义区域未验收前不开放。B 站取流另行规划，暂由用户手动使用官网并交回提取文字；不扩展自动投稿或 B 站抓取。
- **验收**：自动选文件、填入文案/密码、生成并下载，重新选择生成视频读取，载荷逐字一致；独立视频＋`.tkey` 经密送自动编排恢复最终原文。超时、取消、下载失败、错密码和页面变化不伪报成功，不重复已完成的网盘上传。
- **顺序**：文字链→钥匙→帧语 RPA→发布和界面接线→验收。先用少量合成素材完成实际网站验证，再扩大参数范围；不把净室研究设为该版本前置条件。
- **发布边界**：本条纳入 v0.2 目标，真实支持范围以测试为准；① 等既有成果不回退，⑧④⑦⑨a 保留在同版待办。官网故障时保留已生成的分享/文字并可重试，不声称视频路径离线可用。

执行入口：[分阶段计划](plans/2026-10-29-text-pipeline/README.md)与[并行分包/派发模板](plans/2026-10-29-text-pipeline/PARALLEL.md)。两份净室提示词保留在下方“后续研究”，当前不执行。

文字链、钥匙、网页载体、CLI/API、桌面编辑/还原和发布逐方案续跑均已接通，见[集成说明](dev/text-delivery.md)及[发布验收](releases/0.2.0.md)。

### ⑧ 登录态有效性检查（已接线）

- 账号页提供单盘/批量有界检查，区分未登录、已登录、已检测、已过期、网络错误、人工验证和不确定状态；检查不代替用户登录。
- **批量检查**：`misong account check --all [--headless]` 与账号页“全部检查”。只打开文件页判断登录状态，不上传、不改动。
- **发布前预检**：开始任务前只检查本次会用到的网盘；过期则提示先重新登录，避免跑到中途才失败。
- **注意**：部分网盘无头模式会触发风控，失败时回退有头；检查结果不记录 Cookie。
- **验收**：六盘合成页面覆盖有效、失效及故障分类，预检能阻止失败账号开始上传；2026-10-31 真实只读复验覆盖五盘已登录、夸克/123/百度隔离未登录及迅雷真实过期，结果与限制见[六盘验收报告](dev/v020-live-sixdisks.md)。迅雷已登录态待所有者扫码，五盘真实自然过期态暂无样本，不宣称真实六盘完整双状态矩阵全部通过。

### ④ 驱动自检（默认两级已接线）

分三级，默认只做前两级：

1. **环境**：`misong doctor` 检查 Python、依赖、Playwright、浏览器通道、7-Zip、Node。
   本级 CLI 与 JSON 报告已实现；第二级 selfcheck 已实现，第三级可选主动写入金丝雀尚未开放，明确报告不支持。
2. **只读选择器**：`misong selfcheck --disk <盘>`，打开网盘页面，逐个确认上传、新建文件夹、分享入口等关键元素存在。每个驱动声明自己的关键选择器清单，不做任何写操作。
3. **金丝雀（可选）**：上传 1 KB 文件到 `misong-selftest/`，创建分享、读回、删除。

- 失败默认返回脱敏的逐项报告；明确启用 `selfcheck --diagnostics` 或界面开关时保存原始截图/HTML 到本机私密状态目录，诊断包默认仍只列清单，不附带内容。
- Issue 模板要求附自检报告。
- **验收**：人为改坏一个选择器，自检能准确指出是哪一步、哪个元素失败。

### ⑦ 诊断包导出与模板导入导出（已接线）

- **诊断包**：`misong diag export` 与设置页“导出诊断包”，内容为版本、系统、依赖版本、白名单结构化事件、明确选中任务的公开概要、检查报告和失败快照清单。截图默认不包含，勾选时提示可能含账号信息；不直接打包原始计划文件。
- **模板**：导出为带 `schema_version` 的 JSON，只含选项，不含密码和账号；导入时校验字段，名称冲突时自动重命名。
- **验收**：诊断包中检索不到任何真实链接、提取码、密码和 Cookie（用固定样本做测试）。

### ⑨a 智能体 Skill 文档（已完成）

- 编写 `skills/misong/SKILL.md`：教智能体用现有 CLI 完成打包、发布、续跑、还原、编解码，并写明安全约束（登录由人完成、发布前确认、不回显密码）。
  [Skill 与参考文档](../skills/misong/SKILL.md)已覆盖现有入口；CLI 尚无交互密码选项的操作明确引导桌面或用户自行执行，不编造参数。

## 0.3 好安装

### ③ 打包 exe / 安装器 + 版本检查

- **发布方完整版**：PyInstaller onedir（Nuitka 作备选，权衡体积与误报）。不内置 Chromium，使用系统已装的 Chrome / Edge 通道；7-Zip 已随附。
- **Node 依赖**：乱码编码器需要 Node。方案二选一：随附 `node.exe`，或检测系统 Node，缺失时提示改用在线版。
- **安装器**：Inno Setup，安装到用户目录，无需管理员权限；依赖前置工作“数据目录可配置”。
- **接收方便携版**：基础包只含文件还原与纯文字解码，不含 Playwright，单文件 exe，体积尽量小；帧语视频自动还原需要带浏览器依赖的版本或可选组件，基础包保留手动官网提取后继续还原文字的入口。
- **版本检查**：启动时查询 GitHub Releases 最新版本，只提示不自动下载；离线或失败时静默；可在设置中关闭。
- **CI**：GitHub Actions（`windows-latest`）跑测试、打包、上传构件；推送标签时自动建 Release 并附 SHA-256。
- **风险**：未签名程序会触发 SmartScreen 警告，PyInstaller 产物易被杀软误报。文档说明原因并提供校验值。

### ⑥ 密码生成器与组合导出

- 用 `secrets` 生成；可选长度、字符集，默认排除易混字符（`0O1lI`）；提供易读的词组模式。可每层独立或统一。
- 发布完成后可**显式**导出“文案 + 密码”组合（文本 / Markdown / 剪贴板），导出前提示明文风险，并建议文案和密码分开发送。
- 默认仍不保存密码。若用户为了补链（②）选择保存，使用 Windows DPAPI 加密并明确告知风险。

## 0.4 规模化

### ⑤ 批量 / 队列发布

- 现状：一次一个任务，按网盘加独占锁。
- **队列**：持久化队列文件；每项 = 源文件 + 模板；默认顺序执行；单项失败不阻塞后续，可重试。
- **任务中心**：排队 / 运行 / 失败 / 完成，支持暂停、取消、调整顺序。CLI：`misong queue add|list|run`。
- **风控**：每项之间随机间隔，可配置每盘每日上限。
- 依赖 ⑧（开跑前统一预检）和 ⑥（批量生成密码）。

### ② 链接体检与一键补链

- **体检**：在不带登录的独立浏览器上下文里打开分享页，判定为正常 / 已失效 / 已取消 / 文件丢失（迅雷曾出现“分享仍在但无文件”）/ 需要验证 / 未知。默认手动触发，可选每天一次（应用内定时或 Windows 任务计划）。结果写回任务记录，失效项在界面标红。
- **补链**（必须用户确认，不自动重传）：
  - 打包产物仍在：复用已保存任务，只重跑失效阶段的上传和分享。
  - 产物已清理：需要原文件和密码重新打包（密码不保存，需用户输入，或使用 ⑥ 的可选加密保存）。
  - 中转链：只重建失效那一跳，并更新最终文案（复用现有回填机制）。
- **范围**：先做百度、夸克，再逐盘扩展。注意匿名访问频率。

## 0.5 智能体

### ⑨b CLI 机器可读输出 + MCP 服务

- **CLI 稳定化**：所有子命令支持 `--json` 输出和规范的退出码；密码只能通过环境变量、标准输入或文件传入，不经命令行参数。
- **MCP 服务**：`misong mcp`（标准输入输出，作为可选依赖）。工具：状态与自检、账号检查、打包、发布、任务列表与续跑、还原、编解码。
- **安全约束**：发布默认先返回计划预览，需带确认参数才执行；不提供登录工具（登录必须由人在浏览器完成）；工具结果不回显密码；可限制允许访问的目录。

## 后续研究（未排期，不作为 v0.2 前置条件）

- **帧语自主兼容/授权本地集成**：当官网依赖、实际 RPA 维护成本或离线需求值得投入时再评估。未来适配器复用第四步方案、载体接口和 `.tkey`，先验证兼容再替换，当前不承诺时间和覆盖模式。
- 净室材料保留：[备用兼容计划](plans/2026-10-29-text-pipeline/03-framewords-compat.md)、[行为侧提示词](plans/2026-10-29-text-pipeline/prompts/behavior-agent.md)、[实现侧提示词](plans/2026-10-29-text-pipeline/prompts/implementation-agent.md)。须用户明确启动后使用，原实现研究材料仍不能进入净室实现上下文。

## 暂不做

- 自动处理验证码、绕过风控、保存账号密码自动登录。
- 无人确认的自动重传。
- 内置网盘下载器：接收方仍使用网盘官方网页或客户端下载。
