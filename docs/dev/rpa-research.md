# 网盘 RPA 现场机制与调研

本文记录 2026-10 开发期间对各网盘网页的现场观察和调研依据；站点随时可能改版。
当前验收范围与待办见[支持情况](../status.md)，驱动约定见[开发指南](development.md)。

## 六盘分享设置现场补充

夸克、飞猫、UC、迅雷、123 均已查看实际分享设置。具体能力表和 UI 交集规则见
[使用指南](../user-guide.md#多盘选择与统一分享设置)。夸克7天带码、UC/123带码及无提取码、
飞猫长期私密目录均已实际创建。迅雷关闭快速访问后可在弹窗读到显式提取码，接收页已验证可用。
百度分享弹窗已实测 1/7/30/365天/永久和随机/自定义提取码，没有“无提取码”；链接、
提取码和实际期限从 `/share/pset` 响应回读，选择不符时驱动会重设并重试一次。

## 实地观察与实现边界

后续六盘扩展已统一名称、域名及 GUI 入口。独立引擎已实际完成夸克、飞猫、UC、迅雷、123的上传分享。
UC、迅雷、123的同一多盘任务均已确认5/5文件与7天带码分享，三版合并文案逐一解码一致。
123首次登录的会员推广和上传进度面板均通过真实关闭控件收起，避免遮住后续操作；
分享工具栏限定直接子控件，排除屏外测量用的重复“分享”。不能把仅完成首卷当成整批成功。
迅雷传输列表会在上传后遮住工具栏，驱动用实际标题栏关闭按钮收起，再上传下个文件或分享。
该容器外层可为零高度，检测实际可见关闭按钮，不使用强制点击或移除遮罩。
百度使用产品自己的 Playwright 专用档案完成扫码登录、复用会话、上传、目录分享与取链。

百度现场确认的控件与流程：文件行 `.wp-s-pan-table__body-row`，文件名
`a.list-name-text`，行内勾选块 `.wp-s-pan-table__body-row--checkbox-block`；
“上传”本身是可见的 `input[type=file][name=html5uploader]`，“新建文件夹”是表内
`textarea.u-textarea__inner` 内联输入（Enter 提交）。目录路由在 hash 的 `path=` 参数；
进入目录时观察站点自己的 `/api/list?dir=` 响应取得精确字节数，上传完成以文件表中
出现精确同名行为准，传输面板的“上传完成”文字不算确认。根目录操作前整页重载，
避免 SPA 路由切换期间残留的上一目录行被误点。
分享弹窗 `[role=dialog][aria-label^="分享文件(夹):"]` 当前提供 1/7/30/365天/永久
与随机/自定义提取码（没有“无提取码”）；点击“复制链接”触发 `/share/pset`，
链接、提取码（二维码 URL 的 `pwd` 参数）和 `expiredType` 从该响应回读。
弹窗会异步载入配置并可能推迟按钮可用，驱动先等待内容稳定再设置选项，
有效期响应不符时重设并重试一次。匿名接收方可打开链接、输入提取码并查看目录，
但下载会要求登录百度账号，这是平台限制。
推广弹窗、零高度传输遮罩及重复分享控件均有本地模拟站点回归覆盖。

夸克：项目 Python Playwright 引擎完成登录 → 新建独立测试目录 → 上传两个 ZIP 字节分卷、
两份清单与 RESTORE.txt → 分享目录 → 打开分享链接查看全部五个文件，并生成三版文案，
兽曰、魔曰、哈基米逐一解码与链接原文一致。测试数据是程序生成的普通文字。

现场确认的夸克控件：`tr.ant-table-row`、`input.input-edit` 内联目录命名（Enter 提交）、
双击文件名进入目录、`.bcrumb-filename` 目录面包屑、`.fl-refresh` 刷新文件列表、
分享弹窗“创建分享”、成功弹窗原始有效期描述。
上传结果必须在文件列表内确认，不能拿传输队列里的同名文字当成上传成功。
夸克驱动还等待站点自身刷新列表请求的响应，核对文件名、大小和所在目录，以免
页面延迟渲染时把已经上传的文件误判为缺失并生成重名副本；恢复期间已发现并修复此问题。
网盘有时不会及时刷新文件列表：上传等待期间每五秒只刷新文件列表，不重载页面。

页面预置的封禁提示组件可能位于屏幕上方（`out-screen`），即使 `is_visible()` 为真，
也不能据此断言账号被封禁。驱动同时检查视口交集，只对当前显示的提示暂停操作。
此次曾错误把辅助功能树中的模板文案当成实际错误，已通过真实上传与分享纠正。

飞猫盘实际文件页是 `/files`。
现场确认：`#fc-content .file-item-hover` 为文件行，`.openFoldername .edit-input input`
内联命名后按 Enter，`.one .small-name` 为目录面包屑，`button.icon-refresh` 刷新列表。
通过文件行 `.icon_checks_wrap` 勾选后，使用 `.multiple-operation` 操作栏。

2026-10-24 会话补测：Chromium、Chrome 的本地合成 Cookie 实验都重现了持久档案关闭后丢失会话 Cookie、
认证快照仍保留它们的差异。运行时现于首次认证导航前补回缺失的会话 Cookie，保留档案现有存储。
修复后的真实任务已完成一个完整 MP4 的上传、长期带码分享和本地产物清理；任务浏览器关闭后，
另一新浏览器复用会话并完成新目录的两文件上传和目录分享。
同一 PHPSESSID 在数次页面操作后的剩余期限约 24 分钟，到期时间向后移动；这只是本次 Cookie 滑动续期的观察，
不能当作服务端会话的固定寿命。精确扫码时间和完全空闲的失效时间未测；匿名接收页尚待手动输入访问密码，
不能据此更新下文的目录发布机制或宣称门面视频网页可播。

部分飞猫账号（如微信注册）在上传和分享前要求绑定手机号；这属于账号前置条件，
软件不代填手机号、验证码或密码。驱动有头模式等待账号前置完成，无头则暂停。

现场发现：目录分享隐藏未单独发布的文件，只创建目录链接会得到空目录。应先发布文件，
单文件直接使用文件链接，多文件逐个发布后再分享目录。创建链接前须保持“无收益模式”。
真实短域名为 `cm1.hk`，同时兼容 `cm2.hk`；文件路径 `/s/`，目录路径 `/f/`。
弹窗“取件码”是文件定位码，不是访问密码，公开链接的 ShareInfo.code 留空。
在产品专用浏览器内通过 APP 扫码完成登录后，已自动上传两种指引、创建长期公开分享，
并完成简易/复杂中转的三版文案生成。重开以及无头模式均复用会话成功，六份文案解码一致。
两份飞猫下载文件字节一致；加密指引错误密码被拒绝，正确密码解出内容与本地 guide.txt 一致。
夸克五个本体文件逐个实际下载后，SHA-256 全部一致；合卷、7z→ZIP→LZ4→TAR 还原的
两个源文件逐字节一致，ffprobe 仍识别合并视频。夸克网页拒绝多文件批量下载，单文件可正常下载。
真实中转验收覆盖飞猫单文件第一跳；飞猫多文件目录模式仅经驱动测试，尚未现场验收。
文件页说明普通用户单文件上限为 4G、达人用户为 10G；这是页面声明，未做边界上传实测。
百度已完成自动上传、目录合集分享和三版文案真实验收：6文件任务7天带码分享，
暂停续跑（1/2 与 9/9）无重复副本，永久有效与平台默认（365天）均实测；
三版文案逐字解码一致，接收端打开分享并输码可见全部计划文件。
已登录会话从分享页下载与文件管理器逐文件下载的 SHA-256 全部一致，
合卷、解包还原与原始资源逐字节一致。匿名下载需登录，见上文。

没有通过边界上传确认各账号单文件上限。`1900M` 只是保守分卷默认值；
真实限制还取决于网页/客户端、会员和账号容量。不能把一次微小文件成功推广成大文件保证。
夸克官方分享帮助说明有效期、提取码和访问人数选项，见
[文件分享与快传](https://www.quark.cn/documents/help/file-share)。

## panAI 参考

[52fisher/panAI](https://github.com/52fisher/panAI) 的工作是识别页面选中文本中的
网盘链接、解析已有提取码并辅助填入分享页面。其 `hash` 是 URL fragment 路由/存储
方式，不是文件 MD5/SHA1 秒传算法。它没有替代上传、鉴权或网盘的分享创建 API。
本项目参考它对 URL 参数、提取码文字、平台域名的分类方式，独立实现小型分享文本解析器，
没有复制或内置该脚本。仓库 README 与脚本头部的许可证描述还不一致，整合源码前须逐文件确认。

## 验证码候选

| 项目 | 实际机制 | 适用范围与接入条件 | 处理 |
|---|---|---|---|
| [AI 验证码自动识别填充](https://github.com/ezyshu/UserScript/tree/main/CAPTCHA-automatic-recognition) / [Greasy Fork 540822](https://greasyfork.org/scripts/540822) | 油猴脚本、站点图片与输入框选择器、外部视觉模型 API | 作者说明支持 OpenAI / Gemini / 通义千问，需 API key；图像会发给所配置服务；脚本不是独立浏览器 OCR 引擎 | 已调研，未安装、未请求 API key，也未把账号页面发给第三方模型 |
| [ddddocr-webjs](https://github.com/rexchill/ddddocr-webjs) | 浏览器内 ONNX Runtime Web，本地模型与字符集缓存 | 图片文字 OCR；需模型、白名单和用户脚本管理器或扩展；首次设置不等于已适配所有网盘 | 适合作为本地静态文字验证码候选，未混入 RPA 运行环境 |
| [Captcha Helper](https://github.com/hongshuo-wang/local-captcha-solver) | 本地浏览器扩展 | README 将静态文字/简单算术与实验滑块能力分开说明；复杂行为验证、动态图像等不能假定适用 | 保留候选，未自动授予扩展浏览器权限 |
| [ddddocr](https://github.com/sml2h3/ddddocr) | 本地 OCR SDK | 可以做可选的静态图片识别模块，但仍需现场定位图片、输入框并验证准确率 | 不作为基础依赖，不宣称解决扫码、短信、二次验证 |

当前采用首次人工登录和会话复用，必要时让用户在已打开的浏览器中完成验证。
未实现通用验证码自动破解，未安装扩展或外部打码服务。对自动识别的未来接入应采用
按站点显式启用、有限尝试和可暂停恢复，不能对每次失败重复提交导致账号风控。

## 浏览器选择

软件必须独立运行，所以使用 Python Playwright 的专用浏览器档案，不依赖开发工具或个人浏览器的会话。
登录成功即保存，窗口保持打开直到用户主动关闭。有头模式登录与发布均取消认证前的五分钟超时；
无头模式未确认登录时30秒退出，单文件上传确认仍保留独立超时。
发布任务则在上传分享完成后关闭其任务浏览器。

支持用 `--browser chrome` / `--browser msedge` 选择本机正式版 Chrome/Edge，GUI 账号页
同样可选；启动成功后按网盘记住选择，后续发布沿用。默认使用 Playwright 自带 Chromium，
它通常比正式版更早更新，不能直接称为 Chrome Beta。飞猫曾在正式版 Chrome 中
密码登录触发极验 60500，APP 扫码成功；不能据此断定 60500 与浏览器版本有关。
渠道说明见 [Playwright 官方浏览器文档](https://playwright.dev/python/docs/browsers)。

[极验官方帮助](https://www.geetest.com/Helper) 将 60500 解释为短时频繁验证触发的限制，
建议间隔 30 分钟再试；仅凭该弹窗不能判断网盘账号被封。未实现连续验证码重试或风控绕过。

[Playwright 登录态文档](https://playwright.dev/python/docs/auth#session-storage) 说明常规
storage_state 不包含 sessionStorage。现场重开时飞猫显示“当前设备已被下线”，原驱动还
把匿名页面的 `#fc-content` 误判成登录成功。已改用非空 `.user_info .name` 及下线弹层检查，
保存成功后才进入上传，退出时不把匿名页面覆盖为认证快照。
飞猫现在使用软件专用持久档案（按网盘及浏览器渠道隔离），同时按来源保存/恢复 sessionStorage。
初始遗漏的标签页会话已补齐，显式登录时定期保存，后续重开与无头发布现场成功复用。
会员推广关闭按钮有时仍存在于被遮住的模板内，必须检测中心点可点击后再操作；
窄窗口中“分享”会进入“更多”菜单，已补齐这条正常路径。
以上浏览器档案和状态均在被忽略的 `rpa/state/`，不得提交，也未复用用户个人 Chrome 档案。
`account probe` 和显式启用的 `--diagnostics` 可能保存含私密内容的页面截图，仅留在
`rpa/state/`，不得复制进提交或文档。
